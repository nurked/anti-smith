## Known limitations

### Automation framework globals (`detector.automation-globals`)

- Only sees the main world: anything a framework keeps in an isolated world (Playwright utility world, extension content scripts) is invisible.
- Patched ChromeDriver builds rename the cdc_ variables; stealth tooling removes the rest.
- __puppeteer_evaluation_script__ is normally a sourceURL in stack traces, not a global — see detector.sensitive-reads for stack markers.

### Screenshot / emulation hints (`detector.capture-hints`)

- DevTools device emulation also changes only the viewport; busy main threads also stall frames.
- Screenshots taken by the OS or by a computer-use agent watching the screen leave no trace in the page.
- Unverified hypothesis: whether Page.captureScreenshot stalls frames measurably varies by Chrome version — see docs/test-plan.md.

### CDP attached (console serialization) (`detector.cdp-console`)

- Fires for humans with DevTools open; undocked DevTools cannot be told apart from automation.
- Recent V8 reads Error.stack internally without calling user getters, which silences the classic variant (reported by Castle, 2025).
- Frameworks that avoid Runtime.enable, and WebDriver BiDi sessions, do not trigger it.

### Debugger pause timing (`detector.debugger-timing`)

- Automation frameworks rarely enable the Debugger domain, so this mostly measures DevTools users.
- Interrupts anyone with DevTools open at every check.
- Busy main threads can create false long gaps; the threshold is generous for that reason.

### Foreign DOM changes (`detector.dom-mutations`)

- Many ordinary extensions (password managers, Grammarly, translators, ad blockers) inject DOM too, so this tops out at suspicious.
- Closed shadow roots and shadow roots attached from an isolated world are not visible; only main-world attachShadow calls are observed.
- Pages that build DOM at runtime must call runtime.adoptPending() right after rendering (see packages/embed integrations), claim nodes with runtime.claim, or mark containers with data-as-ignore — or they will flag themselves. Anything injected in the same task as a page render is adopted along with it.

### Agent extension probe (`detector.extension-probe`)

- Installed is not the same as active: the person may have the extension but not be using it right now.
- Manifest V3 extensions can set use_dynamic_url, which makes resource URLs unguessable; extensions without web-accessible resources cannot be probed.
- Chromium only. Probing installed extensions is device fingerprinting — check consent requirements (ePrivacy/GDPR) before using it in production.

### Focus, scroll and hidden-tab input (`detector.focus-scroll`)

- Autofocus, anchor links, find-in-page, scrollbar drags and smooth-scroll tails cause some unexplained focus/scroll.
- An agent that keeps the tab focused and visible (most do while acting) passes the hidden-input check.
- document.hasFocus and visibilityState are captured at start; patches applied before load can still lie.

### Headless browser signs (`detector.headless`)

- New headless Chrome (--headless=new) and stealth plugins fix most of these.
- Software WebGL (SwiftShader, llvmpipe) also appears in VMs, remote desktops and GPU-blocklisted machines.
- Extension agents run in a real headed browser and pass every check.

### Honeypots and canary token (`detector.honeypots`)

- Agents that act only on visible elements, screenshots or the accessibility tree never touch the traps.
- Some password managers fill hidden inputs; the trap input uses a non-credential name and autocomplete=off to reduce this.
- The canary only helps if something downstream (server logs, form handlers, support inbox) is searched for it.
- In-viewport traps cover a 2×2 px spot at the top-left and bottom-left corners; a person clicking exactly there would trip them.

### Untrusted (synthetic) events (`detector.input-trust`)

- CDP input (Playwright, Puppeteer, chrome.debugger extensions) produces trusted events and passes.
- The page’s own code may dispatch synthetic events (some UI libraries do); list those types in ignoreTypes.
- Never logs key values or typed text — only event types and targets.

### Interaction timing (`detector.interaction-timing`)

- Keyboard-only users and people who read without touching the mouse look like stop-and-go.
- Timing alone is easy to randomise; it is a supporting signal only.

### Keyboard dynamics (`detector.keyboard-dynamics`)

- Dictation, IME composition and some accessibility keyboards insert text without keydown events.
- Password managers and browser autofill are excluded by inputType, but not all of them set it.
- Agents adding random, human-speed delays between keystrokes will pass the rhythm and speed checks.
- Text expanders and keyboard macros also type faster than people; superhuman speed alone is only suspicious.

### Mouse dynamics before clicks (`detector.mouse-dynamics`)

- Voice control, switch access and some screen readers also click without moving — never block on this alone.
- Touch and pen are excluded; keyboard-activated clicks (detail = 0) are skipped.
- Agents that synthesise curved, jittery paths with off-centre targets will pass.

### Patched native functions (`detector.native-patches`)

- Legitimate libraries patch some of these too (zone.js and error trackers wrap addEventListener; privacy extensions patch canvas). Those count as suspicious, not detected.
- A careful stealth kit patches the iframe realm as well, or uses Proxy objects that stringify as native. puppeteer-extra-plugin-stealth passes this detector (2026-10-24); its spoofed values are caught by detector.headless and detector.permissions-consistency instead.
- Patches made by anti-smith itself are skipped via ctx.isOwnPatch().

### Notification permission consistency (`detector.permissions-consistency`)

- Fixed in new headless Chrome and patched by stealth plugins.
- Some privacy extensions and enterprise policies also produce mismatches.

### Scroll-into-view then click (`detector.scroll-then-click`)

- Only fires when the target was off-screen; agents clicking visible elements never scroll.
- Anchor links, find-in-page and focus-driven scrolling followed by a very fast click could match; the window is kept short to limit this.
- Scrollbar drags send no wheel event; a pointerdown on the scrollbar counts as an explanation, which most browsers provide.

### Sensitive content reads (`detector.sensitive-reads`)

- Only catches scripts in the page main world. Isolated-world content scripts and CDP DOM/accessibility/screenshot reads are invisible.
- Page code (analytics, session replay, rich-text editors) reading the same content will trip it; list known callers in allowStackPatterns.
- new Range() via the constructor is not observed, only document.createRange().

### navigator.webdriver flag (`detector.webdriver`)

- Hidden by stealth plugins and by launching Chromium with --disable-blink-features=AutomationControlled.
- Extension agents (e.g. Claude for Chrome) run in a normal profile and never set it.
